## 1. 引号与转义的作用

Bash 命令行中的空格、星号、美元符号、反引号等字符，可能具有特殊含义。

例如，假设当前目录下有一个名为 `My File` 的目录。

直接执行：

```
cd My File
```

Shell 通常会将其解析为两个参数：

```
参数1：My参数2：File
```

因此，`cd` 无法将它们当成一个目录名。

下面三种写法都可以正确进入该目录：

```
cd 'My File'cd "My File"cd My\ File
```

引号和转义主要有两个作用：

1. **控制特殊字符的解释方式**：例如，让 `*` 保持字面含义，而不是匹配多个文件。

2. **保护参数边界**：例如，让包含空格的路径仍然作为一个完整参数传递给命令。

需要注意，引号不只是控制输出内容。它们会影响 Bash 如何解析命令行、如何形成参数，以及哪些展开操作会执行。

## 2. Bash 如何解析命令

理解引号之前，需要先了解几个重要概念。

| 概念    | 说明                    | 示例                 |
| ----- | --------------------- | ------------------ |
| 参数分隔  | 未引用的空格、制表符等通常用于分隔参数   | `echo hello world` |
| 参数展开  | 读取变量或特殊参数的值           | `$HOME`、`${USER}`  |
| 命令替换  | 执行命令，并用其标准输出替换表达式     | `$(date)`          |
| 算术展开  | 执行整数算术计算              | `$((2 + 3))`       |
| 路径名展开 | 使用通配符匹配文件名            | `*.txt`            |
| 单词拆分  | 对未引用的展开结果按 `IFS` 规则拆分 | `$files`           |
| 引号移除  | 解析完成后，语法引号通常不会传递给程序   | `"hello world"`    |

例如：

```
name="My File"printf '<%s>\n' $nameprintf '<%s>\n' "$name"
```

第一条命令可能输出：

```
<My><File>
```

因为未引用的变量展开结果会发生单词拆分。

第二条命令输出：

```
<My File>
```

因为双引号保护了参数边界。

这里的尖括号只是为了帮助观察参数的起止位置，并不是 Bash 自动添加的字符。

## 3. 单引号

### 3.1 基本规则

单引号使用一对 `'` 包围字符串。

```
'字符串内容'
```

单引号内部的字符基本都按字面内容处理。Bash 不会在其中执行普通的变量展开、命令替换、算术展开或通配符展开。

例如：

```
os=linuxecho '$os'echo '${os} system'echo '*.txt'echo '$(date)'
```

输出：

```
$os${os} system*.txt$(date)
```

即使内容中包含 `$`、`*`、`?`、`>`、`|` 等字符，Bash 也不会将它们作为通常的 Shell 语法执行。

### 3.2 单引号适合什么场景

**场景一：输出字面上的变量表达式**

```
echo '$HOME'
```

输出：

```
$HOME
```

**场景二：输出字面上的通配符**

```
echo '*.log'
```

输出：

```
*.log
```

**场景三：传递固定文本**

```
grep 'error' application.log
```

这里的单引号让 Shell 将 `error` 作为普通参数传给 `grep`。至于 `grep` 如何解释这个参数，由 `grep` 自身决定。

### 3.3 单引号不能直接嵌套

例如：

```
echo 'It's Linux'
```

这条命令有问题，因为 `It's` 中的单引号会提前结束单引号字符串。

可以改用双引号：

```
echo "It's Linux"
```

也可以拼接不同引用形式：

```
printf '%s\n' 'It'\''s Linux'
```

其中：

```
'It' '\'' 's Linux'
```

在实际解析中，Bash 会将其视为连续的几个片段，最终形成一个包含单引号的参数。

不过，对于这个简单示例，使用双引号通常更加直观。

### 3.4 单引号的限制

单引号内部不能通过直接写 `\'` 来表示一个字面单引号：

```
echo 'It\'s Linux'
```

这并不会像某些编程语言那样工作，因为在普通单引号字符串中，反斜杠不具有这种转义作用。

需要输出单引号时，可以使用：

```
echo "It's Linux"
```

或者：

```
printf '%s\n' 'It'\''s Linux'
```

## 4. 双引号

### 4.1 基本规则

双引号使用一对 `"` 包围字符串。

```
"字符串内容"
```

双引号的作用是保护字符串中的大多数特殊字符，并阻止展开结果发生普通的单词拆分和路径名展开。

但是，双引号中的部分字符仍然具有特殊含义。

| 内容                | 双引号中的行为         |
| ----------------- | --------------- |
| 空格                | 保留在同一个参数中       |
| `*`、`?`           | 不进行 Shell 通配符展开 |
| `$var`            | 仍然执行变量展开        |
| `${var}`          | 仍然执行变量展开        |
| `$(command)`      | 仍然执行命令替换        |
| `$((expression))` | 仍然执行算术展开        |
| `"`               | 需要转义才能作为字面双引号   |
| `\$`              | 输出字面美元符号        |
| `\\`              | 输出字面反斜杠         |

### 4.2 双引号会阻止通配符展开

```
echo "*.txt"
```

输出：

```
*.txt
```

虽然 `*` 在 Shell 中通常是通配符，但在双引号内部，它不会被 Bash 当作路径名展开符号。

再看：

```
echo "<>|*?"
```

输出：

```
<>|*?
```

其中的 `|` 不会被解析成管道，`*` 和 `?` 也不会展开。

### 4.3 双引号不会阻止变量展开

```
os=linuxecho "$os"echo "this is ${os} system"
```

输出：

```
linuxthis is linux system
```

这是双引号和单引号最重要的区别之一：

```
echo '$os'
```

输出字面上的 `$os`。

而：

```
echo "$os"
```

输出变量 `os` 的值。

### 4.4 双引号中的反斜杠

在 Bash 的双引号内部，反斜杠通常只会在以下字符前发挥转义作用：

- `$`

- 反引号 `` ` ``

- `"`

- `\`

- 换行符

例如：

```
printf '%s\n' "\$HOME"
```

输出：

```
$HOME
```

再例如：

```
printf '%s\n' "She said: \"hello\""
```

输出：

```
She said: "hello"
```

反斜杠本身也可以转义：

```
printf '%s\n' "C:\\Temp"
```

输出：

```
C:\Temp
```

如果反斜杠后面跟的是普通字母，例如 `\q`，那么在双引号中通常会保留反斜杠：

```
printf '%s\n' "\q"
```

输出：

```
\q
```

### 4.5 双引号的核心价值

双引号不等于“完全不解释内容”，它的核心作用是：

1. 保留参数内部的空格；

2. 阻止普通的单词拆分；

3. 阻止 Shell 通配符展开；

4. 允许变量、命令替换和算术展开继续执行。

因此，双引号是 Bash 脚本中最常用的引用方式。

## 5. 反斜杠转义

### 5.1 基本规则

反斜杠 `\` 通常用于转义紧随其后的一个字符，使该字符不再具有原本的 Shell 语法含义。

例如：

```
touch \*.txt
```

这里的 `\*` 表示字面上的星号，因此会尝试创建一个名为 `*.txt` 的文件，而不是匹配已有的 `.txt` 文件。

创建带空格的目录：

```
mkdir My\ File
```

输出字面美元符号：

```
echo \$HOME
```

输出字面分号：

```
printf '%s\n' hello\;world
```

这些命令中的反斜杠都在控制 Bash 的解析方式。

### 5.2 反斜杠与引号的关系

下面三种方式都可以处理带空格的目录名：

```
cd My\ Filecd 'My File'cd "My File"
```

它们的效果相似，但语法不同。

- 反斜杠通常只转义紧随其后的一个字符。

- 单引号保护其中的整段内容。

- 双引号保护大多数特殊字符，但仍允许变量和命令替换等展开。

对于简单路径，选择自己最容易读懂的方式即可。

### 5.3 反斜杠续行

如果反斜杠紧挨着换行符，Bash 会将二者作为续行处理。

```
printf '%s\n' hello \  world
```

这相当于继续输入同一条命令。

需要注意，反斜杠和换行符之间不能夹有空格。否则续行效果可能失效。

### 5.4 Shell 转义与命令转义是两回事

考虑：

```
printf '%s\n' '\n'printf '%b\n' '\n'
```

第一条命令输出字面上的 `\n`。

第二条命令使用 `printf` 的 `%b` 格式解释反斜杠序列，因此输出一个换行。

这说明：

- Shell 的引号和转义控制 Shell 如何解析命令行；

- 命令本身可能还有另一套转义规则。

不要将这两套规则混为一谈。

## 6. ANSI-C 引号

### 6.1 什么是 `$'...'`

Bash 支持一种特殊的引用方式：

```
$'字符串内容'
```

它允许使用常见的反斜杠转义序列表示特殊字符。

例如：

```
printf '%s\n' $'first\nsecond'
```

输出两行：

```
firstsecond
```

再例如：

```
printf '%s\n' $'column1\tcolumn2'
```

两个字段之间会出现制表符。

### 6.2 常见转义序列

| 写法     | 含义      |
| ------ | ------- |
| `\n`   | 换行      |
| `\t`   | 水平制表符   |
| `\r`   | 回车      |
| `\\`   | 反斜杠     |
| `\'`   | 单引号     |
| `\"`   | 双引号     |
| `\a`   | 响铃字符    |
| `\b`   | 退格      |
| `\xHH` | 十六进制字节值 |

例如：

```
printf '%s\n' $'It\'s Bash'
```

输出：

```
It's Bash
```

还可以将多行字符串保存到变量中：

```
message=$'line 1\nline 2'printf '%s\n' "$message"
```

### 6.3 使用限制

`$'...'` 是 Bash 等部分 Shell 支持的扩展，不应假定所有 `/bin/sh` 实现都支持它。

如果编写的是 Bash 脚本，通常没有问题：

```
#!/usr/bin/env bash
```

如果目标是兼容多种 POSIX Shell 的脚本，则应检查目标 Shell 的支持情况。

## 7. 变量展开与安全引用

这是 Bash 引号中最值得重点掌握的部分。

### 7.1 为什么变量通常必须加双引号

假设：

```
path="/home/chriskim/project data/test project"
```

变量中包含空格。

如果执行：

```
printf '<%s>\n' $path
```

Bash 可能先展开变量，然后进行单词拆分，得到多个参数。

而：

```
printf '<%s>\n' "$path"
```

会将整个路径作为一个参数传递。

对于删除文件的操作，这种区别尤其重要。

不推荐：

```
rm -rf $path
```

推荐：

```
rm -rf -- "$path"
```

未引用的变量展开可能使路径被拆成多个参数；如果这些参数恰好对应现有文件或目录，就可能发生误删。

**重要：双引号只能保护参数边界，并不能判断目标路径是否正确。** 对 `rm -rf` 这样的破坏性命令，仍然要先确认变量值和操作目标。

可以先检查：

```
printf '准备操作的路径：<%s>\n' "$path"ls -ld -- "$path"
```

### 7.2 为什么使用 `${var}`

下面两种写法都能引用变量：

```
echo "$name"echo "${name}"
```

但当变量名后面紧接普通字符时，大括号可以明确变量边界。

例如：

```
name=Linuxecho "${name}System"
```

输出：

```
LinuxSystem
```

如果写成：

```
echo "$nameSystem"
```

Bash 会尝试读取名为 `nameSystem` 的变量，而不是先读取 `name` 再拼接 `System`。

因此，在需要明确边界的地方，推荐使用 `${var}`。

### 7.3 空变量和未设置变量

```
unset nameprintf '<%s>\n' "$name"
```

输出：

```
<>
```

未设置变量在双引号展开时通常会成为空字符串。

如果希望在变量为空或未设置时提供默认值，可以使用：

```
printf '%s\n' "${name:-unknown}"
```

含义：如果 `name` 未设置或为空，就使用 `unknown`。

而：

```
printf '%s\n' "${name-unknown}"
```

含义：仅当 `name` 未设置时使用 `unknown`；如果它已设置为空字符串，则结果仍为空。

### 7.4 处理多个文件名：使用数组

不推荐把多个文件名拼成普通字符串：

```
files="file one.txt file two.txt"some_command $files
```

这样容易把文件名拆分，导致参数错误。

在 Bash 中，更合适的方式是使用数组：

```
files=("file one.txt" "file two.txt")for file in "${files[@]}"; do    printf '文件：%s\n' "$file"done
```

其中：

```
"${files[@]}"
```

可以让数组的每个元素分别作为一个参数传递。

这对于文件名中含有空格或其他特殊字符的情况非常重要。

### 7.5 `"$@"` 与 `"$*"` 的区别

在 Bash 脚本中，位置参数表示传递给脚本的参数，例如 `$1`、`$2`。

当需要把所有参数转交给另一个命令时，通常应该使用：

```
some_command "$@"
```

`"$@"` 会保留每个参数原有的独立边界。

而：

```
some_command "$*"
```

会将所有位置参数合并成一个字符串。

示例：

```
set -- "one file.txt" "two file.txt"printf '<%s>\n' "$@"printf '<%s>\n' "$*"
```

第一条 `printf` 会收到两个参数。

第二条 `printf` 会收到一个合并后的参数。

因此，包装命令或转发脚本参数时，通常应使用 `"$@"`。

## 8. 命令替换与算术展开

### 8.1 命令替换 `$(...)`

命令替换会执行括号中的命令，并将其标准输出替换到当前位置。

例如：

```
today=$(date +%F)printf '日期：%s\n' "$today"
```

推荐将命令替换的结果放在双引号中：

```
result="$(some_command)"
```

否则，输出中包含的空格可能导致单词拆分，`*` 等字符也可能触发路径名展开。

命令替换还有一个重要特点：它会删除输出末尾的一个或多个换行符。这是命令替换本身的行为，与是否使用双引号无关。

### 8.2 算术展开 `$((...))`

Bash 可以使用算术展开计算整数表达式：

```
count=3printf '%s\n' "$((count + 2))"
```

输出：

```
5
```

双引号不会阻止算术展开。

### 8.3 旧式反引号命令替换

早期的命令替换写法是：

```
today=`date +%F`
```

现在通常更推荐：

```
today=$(date +%F)
```

原因包括：

- `$(...)` 更容易阅读；

- 更容易嵌套；

- 在复杂命令中不需要反复处理反引号的转义。

因此，在现代 Bash 脚本中，优先使用 `$(...)`。

## 9. 路径和文件名中的特殊字符

### 9.1 处理包含空格的路径

```
mkdir -p "My Project"cd "My Project"touch "notes draft.txt"
```

如果使用变量保存路径：

```
file="notes draft.txt"cat -- "$file"
```

这里的 `--` 用于告诉支持该约定的命令：后面不再有选项，即使文件名以 `-` 开头，也不要把它当成选项。

### 9.2 处理以连字符开头的文件名

假设存在一个文件：

```
-important.txt
```

可以这样读取：

```
cat -- '-important.txt'
```

也可以使用明确的相对路径：

```
cat ./-important.txt
```

注意：`--` 是许多常见命令支持的约定，但并非所有程序都支持，具体应查看对应命令的帮助文档。

### 9.3 处理包含特殊字符的文件名

文件名可能包含空格、制表符、通配符，甚至换行符。因此，不应假定文件名永远是一个简单的单词。

Bash 中可以结合 `find -print0` 和 `read -d ''` 处理文件列表：

```
while IFS= read -r -d '' file; do    printf '找到文件：%s\n' "$file"done < <(find . -type f -print0)
```

这里：

- `find -print0` 使用 NUL 字符分隔文件名；

- `IFS=` 防止读取时修剪首尾空白；

- `read -r` 防止反斜杠被 `read` 当成转义；

- `-d ''` 在 Bash 中表示使用 NUL 字符作为分隔符；

- `< <(...)` 是 Bash 的进程替换语法。

这是 Bash 特有的组合用法，不是所有 POSIX Shell 都支持。

## 10. 引号、通配符与正则表达式

### 10.1 Shell 通配符

Shell 常见的路径名展开符号包括：

| 符号      | 含义           |
| ------- | ------------ |
| `*`     | 匹配任意长度的字符序列  |
| `?`     | 匹配一个字符       |
| `[abc]` | 匹配集合中的一个字符   |
| `[a-z]` | 匹配指定范围中的一个字符 |

例如：

```
ls *.txt
```

在通常情况下，Bash 会先把 `*.txt` 展开为当前目录中匹配的文件名，再把这些文件名传给 `ls`。

如果想让星号保持字面意义，可以使用：

```
printf '%s\n' '*.txt'
```

或者：

```
printf '%s\n' \*.txt
```

### 10.2 Shell 通配符和正则表达式不是一回事

例如：

```
grep '^[0-9][0-9]*$' file.txt
```

单引号的作用是防止 Shell 对表达式进行展开。引号中的正则表达式会传给 `grep`，再由 `grep` 解释。

而：

```
ls *.txt
```

通常是由 Bash 先进行通配符展开，`ls` 接收到的是匹配到的文件名。

需要记住：

> 引号控制 Shell 的解析；引号内部的内容交给程序后，仍可能被该程序按自己的规则解释。

例如 SQL、正则表达式、`printf` 格式字符串、`awk` 程序等，都有各自的语法。Shell 引号并不会自动使这些内容对所有目标程序都安全。

## 11. Here Document 与 Here String

### 11.1 Here Document：`<<`

Here Document 用于向命令提供多行标准输入。

例如：

```
cat <<EOFHello, $USERToday is $(date +%F)EOF
```

由于分隔符 `EOF` 没有被引用，正文中的变量展开和命令替换会执行。

如果将分隔符引用起来：

```
cat <<'EOF'Hello, $USERToday is $(date +%F)EOF
```

正文中的 `$USER` 和 `$(date +%F)` 就不会被 Shell 展开，而是作为字面文本传给 `cat`。

当需要向命令输入包含大量 `$`、反引号或反斜杠的原始文本时，这种写法非常方便。

### 11.2 `<<-`：去除行首制表符

```
cat <<-EOF    第一行    第二行EOF
```

`<<-` 会去除正文行首的制表符（Tab），但不会去除普通空格。

需要注意，示例中行首必须是实际的 Tab 字符，才能达到相应效果。

### 11.3 Here String：`<<<`

Bash 还提供 Here String，可以将一个字符串作为命令的标准输入，并附加一个换行符。

例如：

```
text="linux shell"grep 'linux' <<< "$text"
```

这属于 Bash 扩展，不是通用的 POSIX Shell 语法。

## 12. 引号与命令执行安全

### 12.1 引号可以保护参数边界，但不能保证操作安全

例如：

```
path="/tmp/my data"rm -rf -- "$path"
```

双引号可以防止路径被空格拆开，`--` 可以防止以连字符开头的路径被当成选项。

但如果 `path` 本身指向了错误的目录，这条命令仍然可能造成严重后果。

执行破坏性命令前，可以先检查：

```
printf '目标路径：<%s>\n' "$path"test -n "$path" && ls -ld -- "$path"
```

特别是涉及 `rm -rf`、批量修改权限、批量移动文件等操作时，应额外验证目标。

### 12.2 谨慎使用 `eval`

`eval` 会将其参数重新作为 Shell 命令解析，因此容易引入命令注入风险。

不推荐：

```
eval "some_command $user_input"
```

如果变量内容来自用户输入或外部数据，就更需要谨慎。

优先使用数组传递参数：

```
args=("first argument" "$user_input")some_command "${args[@]}"
```

这种方式可以保留参数边界，避免不必要的二次 Shell 解析。

### 12.3 `sudo command > file` 的权限陷阱

例如：

```
sudo echo "new value" > /etc/example.conf
```

这条命令可能仍然因为权限不足而失败。

原因是：`>` 重定向由当前 Shell 执行，而不是由 `sudo` 提权后的 `echo` 执行。

可以改用：

```
printf '%s\n' "new value" | sudo tee /etc/example.conf
```

追加内容则使用：

```
printf '%s\n' "new value" | sudo tee -a /etc/example.conf
```

如果文件包含敏感信息，还需要注意 `tee` 默认会将内容输出到标准输出；必要时可以对它的标准输出进行重定向。

## 13. 常见错误与排查

### 错误一：忘记给含空格的变量加双引号

错误：

```
file="report final.txt"cat $file
```

正确：

```
cat -- "$file"
```

### 错误二：误以为双引号会阻止变量展开

```
name=Linuxecho "$name"
```

输出为：

```
Linux
```

如果需要输出字面上的 `$name`，可以使用：

```
echo '$name'
```

或者：

```
echo "\$name"
```

### 错误三：在单引号内部直接放单引号

错误：

```
echo 'It's OK'
```

可以改为：

```
echo "It's OK"
```

### 错误四：以为引号会作为参数传递给程序

```
printf '%s\n' "hello world"
```

`printf` 收到的参数是：

```
hello world
```

其中不包含用于 Shell 语法的双引号字符。

### 错误五：混淆通配符与正则表达式

```
ls '*.txt'
```

这会将字面字符串 `*.txt` 传给 `ls`，通常不会列出匹配文件。

而：

```
grep '.*' file.txt
```

其中的 `.*` 则会由 `grep` 按正则表达式规则解释。

### 错误六：使用 `echo` 调试复杂转义

不同 Shell 或实现对 `echo` 的反斜杠序列、选项等处理可能不同。

需要稳定控制输出时，通常优先使用：

```
printf '%s\n' "$value"
```

### 调试技巧：观察参数边界

可以使用：

```
printf '参数：<%s>\n' "$@"
```

查看每个参数的边界。

如果要检查某个变量：

```
printf '变量值：<%s>\n' "$value"
```

需要查看不可见字符时，可以考虑 Bash `printf` 的 `%q` 格式：

```
printf '%q\n' "$value"
```

它会以适合在 Bash 中重新使用的形式显示参数，便于观察空格、换行等特殊字符。

## 总结

Bash 的引号与转义可以归纳为以下七条原则：

1. **单引号** `**'...'**`：几乎所有内容都按字面文本处理，不执行变量、命令替换或通配符展开。

2. **双引号** `**"..."**`：保护参数边界并抑制通配符展开，但仍然执行变量、命令替换和算术展开。

3. **反斜杠** `**\**`：通常转义下一个字符；在行尾紧接换行时可以用于续行。

4. **ANSI-C 引号** `**$'...'**`：可以通过 `\n`、`\t` 等转义序列表示特殊字符，但属于 Bash 扩展。

5. **变量展开通常加双引号**：优先使用 `"$var"`、`"${var}"`；数组参数通常使用 `"${array[@]}"`；转发位置参数通常使用 `"$@"`。

6. **引号不是所有程序的通用转义机制**：Shell 解析完成后，目标程序仍可能按自己的语法解释参数。

7. **破坏性命令必须验证目标**：引号能保护参数边界，但不能代替对路径和操作结果的检查。

掌握这些规则后，就能更准确地理解 Bash 命令是如何解析的，并减少脚本中的参数错误、路径错误和意外操作。
